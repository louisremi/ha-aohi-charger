AOHI charger — BLE endpoint provisioning

Optional / experimental companion to the ha-aohi-charger Home Assistant integration. Protocol reverse engineering by atc1441.
⚠️ Read before using.
  • This rewrites persistent configuration on your charger. If it goes wrong, the official AOHI app and the cloud integration may stop working until you restore it.
  • The exact factory values cannot currently be read back from the device, so "restore" writes our best-known defaults, not a verified backup. See step 3.
  • Requires Chrome or Edge (Web Bluetooth). Firefox and Safari are not supported.
  • Nothing here is needed for normal use — the cloud integration works without it.

1Connect

Put the charger in pairing mode first. It advertises as AOC-C022-<xx> (older units may use 7231N); tick the box above if it doesn't appear.

2Read current configuration

Safe, read-only. Required before any write is unlocked.

3Probe for a cloud-host read (experimental)

No known command returns the current endpoint URLs, which is why "restore" is best-effort. This sends a few empty-payload commands whose function is undocumented and flags any reply containing http or ws. If one works, note the exact strings — then restore becomes lossless.

4Change endpoint

Each URL is stored in a 39-byte field and must be ≤38 characters (one byte is the terminator). The whole 126-byte frame must fit in a single BLE write, so this needs a negotiated MTU of ~129+. A real AOC-C022 negotiates 517, so this is not a practical concern. This tool still refuses to fragment: a partial write would store a corrupt URL.
—
Restore uses: https://iotservice.iaohi.com:443 and wss://iotservice.iaohi.com/ws/iot1/.
